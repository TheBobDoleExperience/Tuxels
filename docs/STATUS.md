## What Works Right Now

- `cmake -S . -B build -G Ninja && cmake --build build` produces `./build/tuxels`.
- Launching the binary opens a Qt6 main window with Photoshop-style menu stubs (File/Edit/Image/Layer/Select/Filter/View/Window/Help) and a status-bar "Ready".
- Verified headless: `timeout 2 ./build/tuxels -platform offscreen` runs for 2s without crash.
- Canvas shows a composited 1024×768 sample document (white bg, red rectangle, green disc blended Multiply); checkerboard around canvas; Ctrl+wheel zoom, middle/shift+drag pan.
- Layers dock (right) lists layers top-down with per-row visibility toggle, thumbnail, name, blend-mode combo, and opacity slider. Add/Delete/Up/Down via toolbar or Layer menu. Blend-mode or opacity changes trigger recomposite immediately.
- `File → Open…` imports an 8-bit PNG as a single pixel layer; `File → Export As PNG…` composites the document and writes an 8-bit sRGB PNG. PngIO round-trip verified in `test_png_io`.
- Click-drag on the canvas paints a round brush onto the active pixel layer. Brush kernel has hard/soft falloff (hardness ∈ [0,1]) and honors opacity × flow per stamp; spacing is diameter × 10%. `[` / `]` shrink/grow the brush diameter; status bar reports new size. Layer thumbnails refresh on stroke end.
- `Edit → Undo` / `Edit → Redo` (Ctrl+Z / Ctrl+Shift+Z) reverse and replay: paint strokes (via tile-COW snapshots — only touched tiles are recorded), add/delete/reorder layers, visibility toggles, blend-mode changes, and opacity slider commits (one entry per drag, coalesced on release). Undo depth: 64.
- `Layer → Add Layer Mask` attaches a white (fully-reveal) raster mask to the active pixel layer and switches paint target to mask. The layers panel shows a second thumbnail next to the layer thumb; click a thumb to choose paint target (layer or mask), shift-click the mask thumb to toggle enabled (disabled mask has a red tint overlay), right-click for "Delete Mask". All mask ops are undoable.
- **Tools dock (left)**: foreground/background color swatches (click → color picker, X swaps, D resets to black/white) plus size / hardness / opacity / flow sliders that drive the live brush. `[`/`]` and the dock stay in sync.
- **Paint latency fix**: `compose(tree, out, Rect)` overload restricts the tile loop to tiles touched by the current stamp; the canvas partial-recomposites and partial-uploads only those rows per mouse tick. Structural ops (layer add/delete/reorder, blend/opacity/visibility changes) still full-recompose; paint-stroke undo/redo goes through the partial path via `Command::dirtyRect()` which `PaintCommand` computes from its tile snapshot.
- **Brush cursor ring**: concentric black/white 1-px ellipses centered on the cursor, sized to the active tool's `cursorRadiusPx()` × zoom. Only the ring's widget rect is invalidated per mouse move (partial `update()`), so the preview is cheap. `[`/`]` refresh it live.
- **Selection model** (M1-S1): `core/SelectionMask` (1-channel over a document-sized `TuxImage`, tile-sparse fillRect/combine/invert/clone). `Document::selection()` is a nullable `unique_ptr<SelectionMask>`; null = "no selection". `BrushEngine` multiplies per-pixel deposit by `selection->sample(x,y)` so strokes are clipped to the active selection. `Select` menu wired: `All` (Ctrl+A), `Deselect` (Ctrl+D), `Inverse` (Ctrl+Shift+I) — each undoable via a dedicated `SelectionCommand`.
- **Marquee + ants** (M1-S2): ToolsPanel has a picker row with Brush (B) / Marquee (M) buttons. With the Marquee tool active, drag on the canvas builds a rectangular selection; modifiers at press time pick the combine mode — plain = Replace, Shift = Add, Alt = Subtract, Shift+Alt = Intersect. Live rubber-band dashed rect tracks the drag; on release a `SelectionCommand` commits the before/after pair (so the marquee is undoable). A 10 Hz `QTimer` animates the marching-ants overlay (black solid under white dashed, `dashOffset` rotates) around the selection boundary; only the selection's widget-space bbox repaints per tick. The Shift-for-pan gesture is suppressed when the Marquee is active, so Shift+Left adds to the selection instead of panning.
- **Marquee persistent mode** (M1-S2 follow-up): ToolsPanel reveals a Marquee options row with four combine-mode buttons (New / + / − / ∩) when the Marquee tool is active. The selected button drives the combine mode for drags with no modifier keys held at press time; holding Shift / Alt / Shift+Alt still temporarily overrides per Photoshop. This keeps Subtract and Intersect reachable on Linux WMs (GNOME default) that consume Alt-drag for window-move before Qt receives the event.
- **Paint bucket** (M1-S3): ToolsPanel picker row gains a Bucket (G) button; G shortcut switches tools. When the Bucket tool is active, a press on the canvas runs a 4-connected scanline flood fill at that pixel on the active paint target (layer or mask), comparing against the seed's source color with an L∞ tolerance threshold (UI slider 0–255, normalized to [0,1]). Fill is soft-masked by the selection (binary threshold for traversal; per-pixel multiply on the fill alpha for feathered edges) so bucket-inside-selection just works. A Bucket options row (Tolerance / Opacity) appears when the tool is active. The foreground swatch is the shared source of truth for both brush color and fill color. Fill tile-COW snapshots are wrapped in a `PaintCommand`, so each click is one undo step. Non-contiguous (same-color-anywhere) fills are deferred.
- **Magic wand** (M1-S4): picker row gains a Wand (W) button; W shortcut switches tools. A click on the canvas samples the active PixelLayer's pixel color, runs a scanline flood (`floodSelect` in `fill/FloodFill`) with L∞ tolerance, and commits a `SelectionCommand` carrying the combined before/after selection. Combine-mode semantics match the marquee (Replace/Add/Subtract/Intersect — modifiers win when held, persistent-mode buttons cover WM Alt-hijack). Subtract/Intersect further clip the wand traversal to the existing selection so the wand can never escape it. Shift-click on the canvas routes to the wand (not the pan gesture) because `consumesShiftClick()` returns true.
- **Crop** (M1-S5): picker row gains a Crop (C) button; C shortcut switches tools. A drag on the canvas defines the crop rectangle (rubber-band rendered via the new generic `ToolBase::liveRect()` virtual — shared with the marquee). On release with a non-degenerate rect the tool produces a `PendingCrop{rect}` that MainWindow converts into a `CropCommand`. The command's constructor deep-snapshots the pre-crop document (tile-clones of every PixelLayer image + any mask + the active selection), then calls `applyCropInPlace` which replaces each layer's image with a cropped copy, crops the selection mask to the new doc space (collapsing to null if nothing remains selected), and resizes the document. Undo re-installs the deep snapshot; redo re-runs the crop math. Degenerate drags (< 2 px in either axis) are ignored. Crop respects the document bounds by clamping in `CropTool::release`. Interactive Photoshop-style "drag → adjust handles → Enter to commit" is deferred; current behavior is drag-to-commit with Ctrl+Z to recover.
- **.txl native format** (M1-S6 → M2-S0 → M3-S4): `io/TxlIO.{h,cpp}` in `tuxels_core` (pure C++, no Qt). Custom chunked little-endian binary, tile-sparse — writes only present tiles of each PixelLayer image, each mask (when attached), and the selection (when present). Round-trips doc dimensions, active layer, paint target, and per-layer metadata (id / name / visibility / mask-enabled / opacity / blend mode). Bumped to v2 in M2-S0 to record per-layer backing-image width/height and doc-coord origin; v1 files still load with origin=0 and layer dims == doc dims. Bumped to v3 in M3-S4 to dispatch on a per-layer `Kind` byte so non-destructive adjustment layers round-trip alongside pixel layers: `1=Pixel` (unchanged), `2=LevelsAdjustment` (4-channel × 5-float descriptor), `3=CurvesAdjustment` (per-channel u32 point count + `(f32 x, f32 y)` pairs). Adjustment kinds write `LayerWidth=LayerHeight=0` + `OriginX=OriginY=0` + `NumImageTiles=0` sentinels (no backing image) then the kind descriptor then the mask tiles. Adjustment masks reconstruct at doc dims on load (per the `Document::addAdjustmentLayer` auto-mask invariant). v1 + v2 files still load in the v3-aware build — `kVersionV1`/`kVersionV2`/`kVersionCurrent` constants gate the origin-field and adjustment-kind branches; the writer always emits v3. `Document::setLayerIdCounter` seeds the id counter on load so freshly added layers don't collide with loaded ids. UI: `File → Save As…` (Ctrl+Shift+S) writes `.txl`; `File → Open…` filter includes `*.txl *.png` and dispatches on extension. `Export As PNG…` stays on its own menu entry for flattened exports.
- **Layer origin + mask-in-renderTile** (M2-S0): `LayerBase` owns `int originX, originY` (both default 0). `PixelLayer::renderTile` now translates doc tile coords into layer-local coords, intersects with the layer's backing-image rect, and samples — layers can live anywhere on the doc grid. Masks share their owning layer's origin + dimensions; mask sampling is pre-multiplied into the tile's output alpha inside `renderTile` so `compose()` itself stays origin-unaware. `Document::addPixelLayer(TuxImage&&, int ox, int oy, name)` is ready for S1's Place Image. `CropCommand` intersects each layer's doc-space content rect with the crop and translates origins into the new doc; layers with no overlap collapse to 0×0 with origin (0,0). Mask creation in `Add Layer Mask` follows the invariant by sizing masks to `layer->image.{width,height}()` instead of doc dims.
- **Place image** (M2-S1): `File → Place…` (Ctrl+Shift+P) opens an 8-bit PNG and adds it as a new layer on the **current** document (does *not* replace the doc or open a second window). The new layer's origin is centered in the doc via integer floor-div `((docW - imgW) / 2, (docH - imgH) / 2)`, so oversized PNGs hang past the doc edges with their offscreen pixels preserved in the layer's backing image — they become visible once Move, Crop, or doc-resize reveals them. Undo/redo uses the `LayerOpCommand` closure pattern with a shared `stash` that holds the detached layer between undo and redo, so the exact same `PixelLayer` instance round-trips through the history (no re-decode, no image realloc).
- **Move tool** (M2-S2): picker row gains a Move (V) button; V shortcut switches tools and installs `Qt::SizeAllCursor`. A drag on the canvas while Move is active shifts the **active** layer's `(originX, originY)` by the cursor delta — pixels don't change, the layer's backing image + mask are untouched. Live feedback comes for free from the existing dirty-rect path: each `MoveTool::move()` writes the origin directly and reports a union of the pre-move and post-move doc-space footprints as the dirty rect, so the canvas only recomposites the pixels that actually changed. On release a `MoveLayerCommand(layerId, beforeOrigin, afterOrigin)` lands on the undo stack — the command looks up the layer by id (not by index) so a later redo works even if layers have been reordered since the commit. Zero-delta drags produce no undo entry. Non-pixel active layers (none exist yet, but the check is there) are ignored rather than crashing.
- **Select By Color** (M2-S5): picker row gains a "Y" button in the wand slot (Shift+W cycles Magic Wand ↔ Select By Color, matching Photoshop's grouped-tool UX). A click on the canvas samples the active pixel layer's color at that doc-coord (translated to layer-local via origin), walks every present tile in that layer's backing image, and marks every pixel within L∞ tolerance of the seed — non-contiguously. Combine modes work identically to the marquee/wand: modifiers at press-time win (Shift = Add, Alt = Subtract, Shift+Alt = Intersect), else fall through to the shared wand options row. Intersect and Subtract use the existing selection as a traversal clip so the pick never leaks outside the active region. The L∞ `channelDist` helper is shared with the contiguous `floodFill` / `floodSelect` path — both tools' tolerance sliders mean the same thing. Commits as a `SelectionCommand` via the usual `PendingCommit`/`takeCommit` pop in `onLayerPainted`.
- **Lasso + Polygonal Lasso** (M2-S4): ToolsPanel picker row gains L (Lasso) and P (Polygonal Lasso) buttons; L shortcut switches to the freehand lasso. With Lasso active, a drag builds a polyline (1-doc-px chord decimation so slow drags don't balloon), release rasterizes it via `SelectionMask::fillPolygon` (even-odd scanline, half-open edge y-range `[yMin, yMax)` to avoid double-counting at shared vertices, strict-interior edge rule `xa < i+0.5 < xb` via `xStart = floor(xa + 0.5)` and `xEnd = ceil(xb - 0.5)`) and commits a `SelectionCommand` with the combined before/after pair. PolyLasso is click-vertex: each left click appends a vertex, `hover()` tracks the cursor between clicks so `livePath()` emits a trailing rubber-band edge to render, a click within 6 doc-px of vertex 0 (with ≥3 verts) closes, Enter also closes, Escape cancels. Combine modes work exactly like Marquee/Wand — modifiers at press-time win (Shift = Add, Alt = Subtract, Shift+Alt = Intersect), else fall through to the shared lasso options row (New / + / − / ∩) that applies to whichever lasso tool is active. Switching tools while a polygon is in progress silently discards it rather than committing an unclosed shape. Live polyline renders black underlay + white dashed overlay with per-event bbox invalidation via `widgetRectForPath`.
- **Free Transform** (M2-S3): `Edit → Free Transform` (Ctrl+T) or the ToolsPanel "T" button calls `TransformTool::enter(doc)`, which snapshots the active pixel layer's image (cheap shared_ptr-backed tile copy) + origin, zeros scale/rotation deltas, and sizes a scratch `TuxImage` to the doc-bbox AABB of the current transform. Drags on the canvas hit-test: near a corner (within `kCornerHitRadius = 10.f` doc-px) → Scale drag (un-rotates the cursor vector into the pre-rotation frame, then maps to new `scaleX/Y` using the corner's sign); inside the transformed quad → Translate drag (center += delta); outside → Rotate drag (atan2 delta around the center). Each move re-runs `rebuildScratch()` which recomputes corners, resizes the scratch image, and calls `resampleBilinear(src, scratch, dstLocalToSrc)`. `Resample` uses pixel-center sampling, premultiplies RGB by alpha before the 4-tap blend, and drops results whose alpha falls below a `kAlphaEps = 1e-5f` floor to suppress float noise from `std::cos(π/2) ≠ 0`. Preview compose: `CanvasView::setTransformTool` wires the tool; each paint queries `overlay()` (active flag + `LayerOverride{layerId, &scratch, originX, originY}` + 4 corner points) and passes the override into `compose()`, substituting scratch pixels for the real layer without mutating it — masks are deliberately skipped on overrides. The bbox quad (dashed white over black) + four 6×6 white corner dots render on top. Enter: `onTransformAccept` → `commit()` returns a `PendingCommit{layerId, before, after, beforeX/Y, afterX/Y}` (nullopt for identity → no-op); `TransformCommand` wraps it and pushes onto the undo stack; the tool returns to Brush. Escape: `onTransformCancel` → tool's `cancel()` discards the scratch; no undo entry. Tool switch via picker auto-commits via `commitTransformIfActive` in `setActiveTool` so a user who's clearly done can just pick another tool. `TransformCommand::undo/redo` assigns the whole stored `TuxImage` into the layer (tiles are refcounted shared_ptrs, so whole-image copies are cheap) + swaps origin; layer is found by id so a later tree reorder doesn't break redo. **M3-S5 polish:** Shift held during a Scale drag locks `|scaleY| = |scaleX|` (Y sign preserved so flips still work); Shift held during a Rotate drag snaps the delta to the nearest `π/12` (15°) so the user who started at a non-multiple stays consistent; a doc-space pivot (default = bbox center) is draggable as its own `DragMode::Pivot` within `kPivotHitRadius = 8.f` — rotation + scale then pivot around the moved dot, `buildSrcToDoc` is `translate(-sw/2,-sh/2) · translate(cx−px, cy−py) · scale · rotate · translate(px, py)` (reduces to the original identity-pivot formula when `pivot == center`); `CanvasView` paints a crosshair circle at the pivot and now calls `setModifiers` on every mouse-move so Shift held mid-drag actually reaches the tool.
- **Histogram primitive** (M3-S1): `src/core/Histogram.{h,cpp}` ships `computeHistogram(const TuxImage&, const SelectionMask* = nullptr) → Histogram4x256` — a 4×256 bucket histogram (R/G/B + luma `0.299R + 0.587G + 0.114B`) plus a `total` pixel count. Walks present tiles only, doc-clips edge tiles (so whole-tile fills past doc bounds don't leak in), skips `a <= 0`, respects a binary-threshold selection clip (`sample(x,y) >= 0.5`). Pure C++ in `tuxels_core` — no Qt dependency, no allocations. This is the pre-dialog scan Levels (S2) and Curves (S3) will paint as their static histogram backdrop.
- **Levels adjustment** (M3-S2): `Layer → New Adjustment Layer → Levels…` (Ctrl+L). Opens the modal `LevelsDialog` seeded with the doc's histogram (live-computed from the current composite, honours selection) and a freshly-inserted identity `LevelsAdjustment`. Per-channel params (Composite/R/G/B), each with `inBlack/gamma/inWhite/outBlack/outWhite`; sliders + spin boxes stay in sync, gamma slider is log-scaled 0.1..9.99. Each slider edit mutates the layer in place, rebuilds its cached 256-entry `uint8_t` LUT, and triggers a recomposite via `previewChanged` — so the canvas updates live while the dialog is open. Cancel restores the on-open params snapshot; OK commits a `LayerOpCommand` for the add (mirrors `onLayerAdd`). Clicking the "fx" glyph on an existing Levels layer re-opens the dialog via the S0 `editAdjustmentRequested` signal; subsequent edits commit as a `LayerParamsCommand<LevelsAdjustment, std::array<LevelsParams,4>>`. `applyToAccum` is a tile-local loop: composite LUT first (acts on every RGB channel identically), then per-channel LUT; alpha untouched. Mask and opacity ride the existing S0 lerp-back path.
- **Curves adjustment** (M3-S3): `Layer → New Adjustment Layer → Curves…` (Ctrl+M). Opens the modal `CurvesDialog` seeded with the doc's histogram and a freshly-inserted identity `CurvesAdjustment` (per-channel default `[(0,0),(1,1)]`). The 256×256 `CurveEditor` custom widget paints the active channel's histogram bars (faded) as backdrop, a dashed diagonal reference line, a quarter-grid, the LUT curve in the channel's colour (Composite = white, R = red, G = green, B = blue), and draggable control-point dots. Left-click in empty space adds a control point; drag a dot to move it (clamped between its x-neighbours with `1e-4f` padding so the point list stays sorted without a re-sort; endpoints pinned to `x=0` or `x=1`); right-click a dot to remove (enforces a minimum of 2 points so the spline always has a domain). A channel combo above the editor switches the editor's backing `std::vector<SplinePoint>` + the histogram row (Composite uses luma). Live preview via `pointsChanged` emits on every edit; `reject()` restores the on-open snapshot for Cancel. Add commits through `LayerOpCommand`; re-edit from the "fx" thumbnail dispatches via the S2 `dynamic_cast` ladder and commits `LayerParamsCommand<CurvesAdjustment, CurvesAdjustment::PointsArray>`. `src/geom/Spline.{h,cpp}` ships monotone cubic Hermite (`buildLut256` + `evaluateSpline`) with Fritsch-Carlson tangent clamping so the curve never overshoots — pure C++ in `tuxels_core`, local `SplinePoint` struct instead of `QPointF` keeps core Qt-free.
- **Brightness/Contrast + Hue/Saturation adjustments** (M3-S6): `Layer → New Adjustment Layer → Brightness/Contrast…` and `Layer → New Adjustment Layer → Hue/Saturation…` (Ctrl+U; B&C has no accelerator). `BrightnessContrast` caches a single 256-entry `uint8_t` LUT shared across R/G/B (rebuilt on `setParams` via `(v − 0.5) · (1 + contrast) + 0.5 + brightness` with output-side clamp), single-pass `applyToAccum` over the tile; alpha untouched. `HueSaturation` is LUT-free per-pixel RGB↔HSL: rebuild `h' = fmod(h + hueShift + 360, 360)`, scale `s' = clamp(s · (1 + saturation))`, offset `l' = clamp(l + lightness)` per pixel, converting back with `hslToRgb`; transparent pixels (`a <= 0`) skipped so premul zeroes don't leak bogus colour. `BrightnessContrastDialog` has two slider+spinbox rows ([-100, 100] divided by 100), `HueSatDialog` has three rows (hue [-180, 180], sat/light [-100, 100] divided by 100); both mirror `LevelsDialog`'s Q_OBJECT + `previewChanged` + `reject()` snapshot-restore pattern. `MainWindow::onLayerAddBrightnessContrast` + `onLayerAddHueSaturation` mirror `onLayerAddLevels` line-for-line but skip histogram prep (neither dialog paints a backdrop). `onEditAdjustmentRequested` grows two more `dynamic_cast` branches that each commit a `LayerParamsCommand<Layer, Params>` on OK. `.txl` activates kind ordinals **4 = HueSaturation** (12-byte descriptor: 3 floats) and **5 = BrightnessContrast** (8-byte descriptor: 2 floats) in `kindByte()` / `acceptsAdjustmentKinds()` / writer dispatch / reader dispatch — no version bump, stays v3. Mask + opacity ride the existing S0 adjustment compose path, so masked restriction and blend opacity work automatically.
- **Adjustment-layer infrastructure** (M3-S0): `LayerBase` carries a `virtual LayerKind kind()` discriminator (defaults to `Pixel`; `AdjustmentLayer` overrides to `Adjustment`). `AdjustmentLayer` is an abstract header-only subclass with `renderTile` `final`-returning-false + a pure-virtual `applyToAccum(TileCoord tc, Rgba32F* accum)` that subclasses implement to transform the tile accumulator in place. `composeTileRange` dispatches on `kind()` — for pixel layers the existing `renderTile`+blend path runs unchanged; for adjustment layers the accumulator is copied into a scratch buffer, `applyToAccum` rewrites it, and the result is lerped back over the original using `factor = opacity * maskV` (`maskV` is pulled once per tile because adjustment masks are doc-sized and tile-aligned). `accum.a <= 0` pixels are left alone so empty regions stay empty. `Document::addAdjustmentLayer<T>(std::unique_ptr<T>)` appends the layer, auto-attaches a doc-sized white `LayerMask` (`enabled=true`), and flips `paintTarget` to `Mask` so follow-up brush strokes land on the auto-mask by default (matches PS's auto-mask affordance). `LayerRowWidget` renders an "fx" glyph thumbnail for adjustment layers and emits a new `editAdjustmentRequested(LayerBase*)` signal on layer-thumb left-click; `LayersPanel` forwards the signal and `MainWindow::onEditAdjustmentRequested` is a no-op stub until S2 wires Levels. A test-only `InvertAdjustment` in `test_adjustment_layer` exercises the whole path (7 cases covering kind/renderTile sanity, full-opacity invert, 0.5-opacity lerp, masked-quadrant restriction, transparent-accum passthrough, and the `addAdjustmentLayer` auto-mask + paint-target flip).
- **Brush dynamics** (M2-S6): ToolsPanel brush options row gains **Size Jitter**, **Opacity Jitter**, and **Spacing** sliders below Flow. Spacing is 1–100 % (maps linearly to `spacingRatio ∈ [0.01, 1.0]`, default 10 %). At zero-jitter the paint path is byte-for-byte identical to the pre-S6 brush (the branch in `BrushEngine::applyStamp` short-circuits away from the RNG entirely), so the existing alpha-math tests carry over as a regression floor. With jitter > 0, `BrushEngine` reseeds a per-stroke `std::mt19937` from `std::hash<uint64_t>{}(strokeId)` at each `beginStroke` — the stroke id is a monotonic counter by default, pinnable via `setNextStrokeSeedForTesting(id)` for deterministic replay in tests. Each stamp draws `U(-jitter,+jitter)` and scales: effective diameter = `round(D·(1+u))`, floored at 1 and capped at 2×D (so big jitter doesn't blow up stamp cost); effective opacity = `op·(1+v)` clamped to `[0,1]`. Kernel is rebuilt per-stamp via the new static `RoundBrush::buildKernel(D, hardness, out)` into a scratch buffer owned by BrushEngine. `pressureMultiplier` rides on `RoundBrushParams` but is unwired in M2 — tablet integration is M3+ work and doesn't need to round-trip through the params for now.
